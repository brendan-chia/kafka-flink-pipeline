# ADR 004: Separate runtime processes and freeze the v1 wire contract

Status: accepted. Date: 2026-10-08.

The existing host MiniCluster requires local Python/Java installation and cannot
exercise TaskManager loss independently of its JobManager. Existing event
validation has no explicit wire version, despite replay depending on stable
interpretation of retained records.

Use an optional Compose overlay with Flink 2.2.1 / Java 17, one JobManager and
one TaskManager. Both mount the same local checkpoint volume and install the
same Python dependencies. Submit once through the supported Flink CLI. Keep
the metrics observer in a separate process and make continuous traffic opt-in.
The default host workflow remains available for small local experiments.

Use JSON schema v1 plus strict runtime validation. New producer records declare
`schema_version: 1`; historical absence means v1. Explicit unsupported versions
go to the existing lossless DLQ. Extra properties are tolerated, allowing
optional additions. Do not change the meaning of amount, currency, event ID or
timestamp within v1. Breaking changes require a new schema/decoder, compatibility
fixtures and an explicit rollout. Schema validation is a producer-side aid;
the consumer additionally rejects duplicate keys, unsafe Unicode, fractional
cents and future clock skew. The normalized Flink row shape is unchanged.

PostgreSQL remains idempotent by immutable event ID. DLQ remains at-least-once.
The CI recovery scenario forces a checkpoint, verifies writes after it, kills
the TaskManager before another checkpoint, checks the restored checkpoint ID,
and requires duplicate DLQ source identities as evidence of replay. Reports
include observed recovery duration and reconciliation results.

The shared volume is suitable for one Docker host. It is not replicated storage
or JobManager HA; JobManager loss still needs deliberate resubmission/restoration.
Host checkpoints and container paths are not assumed interchangeable. The
optional lakehouse keeps its separate deployment until cross-stack recovery is
verified. CI evidence is generated by actual execution, never prefilled with
performance claims.
